# Buu's Fury prototype D (DBZ3_cart27): matching disassembly

A separate, self-contained tree for the **"prototype D" build of Dragon Ball Z: Buu's Fury** (dump name
`DBZ3_cart27.GBA`). It uses the same disassembler as the main project and gives:

* **A matching disassembly.** `make compare` rebuilds the prototype byte for byte.
* **Shiftable source.** All 71,381 data pointers are symbols. `make shift-test` inserts 0x100 bytes after crt0, plays
  both ROMs through the same route (boot, title, new game, story, walking, menu) and compares 41 checkpoints: all 41 are
  identical.
* **Names from the final game.** Prototype functions are matched to final-game functions. Names known in the final
  game (`../config/symbols.txt`) are carried over, plus a few prototype-only ones (`config/symbols.txt`).
* **`make extras`**: what the prototype tells us about the final game. It writes a function map, a source-file map,
  the story-flag names, text differences and the debug button codes (`docs/differences.md`).

> **No ROM data is included.** Everything is read at build time from your own dump, `proto/baserom.gba`
> (SHA-1 `4594e2d524e2d77cdf0e58ae7512e1052cc5bc02`, 8 MB). `make extras` also reads the final ROM at
> `../baserom.gba`. Its output goes to `build/extras/` and must not be published.

## Quick start
```sh
cd proto
cp /path/to/DBZ3_cart27.GBA baserom.gba
make && make compare          # -> bfproto.gba: OK
make playable                 # -> bfproto_playable.gba (boots in mGBA and other emulators)
make shift-test               # needs libmgba-dev (see the main README)
make extras                   # -> build/extras/*.txt (needs ../baserom.gba; run `make extract` in .. first for text)
```
Tools and packages are the same as for the main project (`../README.md`).

## Booting it
The dump's first instruction branches to 0x08000088, inside the Nintendo logo. The development cartridge was
presumably started another way, so emulators show a white screen. `make playable` (`tools/harness/playable.py`) writes
a copy whose first word branches to crt0 at 0x080000C0, as the final game does. Everything else is unchanged.

## Layout
| | Prototype | Final |
|---|---|---|
| Thumb/ARM code (`.text`) | 0x08000158-0x0804C0F8 (304 KB) | 0x08000158-0x08054FBC (340 KB) |
| Functions found | 4,120 | 4,767 |
| RW image (copied to IWRAM by crt0) | 0x0873FE10, 0xEFC bytes | 0x087B79A4, 0x1004 bytes |
| ROM image ends | 0x08740D0C | 0x087B89A8 |
| Header title / game code / maker | blank / blank / `01` | `DBZBUUSFURY` / `BG3E` / `70` |
| `assert()` source paths | 53 (`T:\Source\...`, `T:\WinGBACore\...`) | 4 |

The crt0, compiler (ARM ADS), WFZ compression and the script VM are the same as in the final game. `config/game.json`
has the layout. The tools in `tools/bfdis` are the shared disassembler, and they gained four general fixes for this
dump: header fields with NUL bytes, an entry branch that isn't `b _start`, UTF-16 string literals in code, and
IWRAM references in the middle of an instruction.

## Files
| Path | What |
|---|---|
| `asm/`, `data/` | the disassembly (generated by `tools/bfdis/gen.py baserom.gba`) |
| `config/` | `game.json` (layout), `symbols.txt` (names), `raw_insns.txt` (3 instructions GNU as encodes differently) |
| `tools/bfdis/`, `tools/wfz/` | disassembler and WFZ decoder (shared with the main project) |
| `tools/harness/` | headless mGBA harness, routes, `shift_test.sh`, `playable.py` |
| `tools/proto/protoinfo.py` | `make extras` |
| `docs/differences.md` | what is different from the final game, and how it was found |
